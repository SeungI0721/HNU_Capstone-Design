
# Smart Shield Risk Algorithm

## 1. 문서 목적

이 문서는 Smart Shield 프로젝트에서 사용하는 위험도 판단 알고리즘의 목적, 입력 데이터, 판단 원칙, 위험도 단계, 제한사항을 정리한다.

Smart Shield의 위험도 판단은 Android 작업자 앱에서 수행한다.

ESP32는 센서 데이터를 수집하고, 작업자 앱은 수신된 데이터를 기반으로 위험도를 계산한다. 관리자 앱은 Firebase에 저장된 위험도 결과를 읽어 표시한다.

---

## 2. 알고리즘 목적

Smart Shield 위험도 알고리즘의 목적은 작업자의 온열질환 위험 가능성과 이상 상태를 조기에 감지하는 것이다.

주요 판단 대상은 다음과 같다.

```text
고온·고습 환경에서의 온열질환 위험 가능성
피부 접촉 온도 상승 추세
활동량 대비 심박수 과상승
낙상 가능성
장시간 움직임 없음
생체 신호 급변
BLE 연결 끊김에 따른 상태 확인 필요
````

---

## 3. 의료기기 아님

본 알고리즘은 의료 진단 알고리즘이 아니다.

다음 표현은 사용하지 않는다.

```text
온열질환 진단
정확한 체온 측정
의료급 산소포화도 측정
낙상 100% 감지
SpO2 기반 열스트레스 판단
HR > 120이면 무조건 위험
TEMP > 37.5이면 무조건 위험
```

권장 표현은 다음과 같다.

```text
온열질환 위험 가능성 조기 감지
피부 접촉 온도 변화 추적
심박수 변화 기반 생리적 부담 추정
IMU 기반 자세 이상 및 낙상 가능성 추정
다중 센서 융합 기반 위험도 판단
산업안전 보조 시스템
```

---

## 4. 위험도 계산 위치

위험도 계산은 Android 작업자 앱에서 수행한다.

```text
ESP32: 센서 데이터 수집 및 BLE 전송
작업자 앱: payload 파싱 및 위험도 계산
Firebase: 위험도 결과 저장
관리자 앱: 위험도 결과 표시
```

ESP32는 최종 위험도를 계산하지 않는다.
ESP32는 작업자 앱에서 받은 `RISK:*` 명령에 따라 RGB LED, 진동모터, 부저를 제어한다.

---

## 5. 입력 데이터

위험도 알고리즘은 다음 데이터를 사용한다.

| 데이터              | 출처                     | 의미          |
| ---------------- | ---------------------- | ----------- |
| `ENV`            | BME280                 | 주변 온도       |
| `HUM`            | BME280                 | 주변 습도       |
| `LUX`            | BH1750                 | 조도          |
| `TEMP`           | MAX30205 / Fever Click | 피부 접촉 온도    |
| `HR`             | MAX30102 / SEN0344     | 심박수 추정값     |
| `SPO2`           | MAX30102 / SEN0344     | 산소포화도 추정값   |
| `AX`, `AY`, `AZ` | MPU6050                | 가속도         |
| `POSTURE`        | MPU6050 기반 판단          | 자세 상태       |
| `BLE 상태`         | Android BLE            | 연결 안정성      |
| `작업 세션`          | 작업자 앱                  | 작업 시작/종료 상태 |

## 6. 센서 데이터 해석 원칙

### TEMP

`TEMP`는 피부 접촉 온도이다.

```text
심부체온이 아니다.
의료용 체온값이 아니다.
절대값보다 baseline 대비 변화량과 지속 상승 추세가 중요하다.
```

### HR

`HR`은 심박수 추정값이다.

```text
절대값 하나로 위험도를 결정하지 않는다.
작업자 개인 기준값 대비 상승량을 중심으로 사용한다.
활동량이 높은 상태의 심박 상승은 작업 강도 영향으로 일부 보정한다.
```

### SPO2

`SPO2`는 산소포화도 추정값이다.

```text
열스트레스 핵심 지표가 아니다.
단독으로 온열질환 위험도를 올리지 않는다.
움직임이 심하면 신뢰도를 낮춘다.
응급 상태 보조 플래그로만 사용한다.
```

### ENV / HUM

`ENV`, `HUM`은 주변 환경 조건이다.

```text
고온·고습 환경일수록 온열질환 위험 가능성이 증가한다.
환경 조건만으로 위험도를 확정하지 않는다.
```

### LUX

`LUX`는 조도값이다.

```text
직사광선 노출 가능성의 보조 지표이다.
복사열을 직접 측정하지 않는다.
단독으로 위험도를 올리지 않는다.
```

### AX / AY / AZ / POSTURE

MPU6050 데이터는 자세와 활동량 판단에 사용한다.

```text
낙상 가능성
움직임 없음
불안정 자세
활동량 대비 HR 해석
```

---

## 7. 기준값 baseline

위험도 계산에서는 작업자 개인의 기준값을 사용하는 것이 중요하다.

### baselineHR

`baselineHR`은 작업 시작 전 안정 구간의 심박수 기준값이다.

```text
의료적 안정시 심박수가 아니다.
당일 착용 상태와 작업 전 상태를 반영한 기준값이다.
```

### baselineTemp

`baselineTemp`는 작업 시작 전 피부 접촉 온도 기준값이다.

```text
심부체온 기준값이 아니다.
센서 착용 상태에서의 피부 접촉 온도 기준값이다.
```

---

## 8. 권장 baseline 설정 방식

현재 구현은 작업 시작 후 정상 상태의 초기 데이터를 기준값으로 사용할 수 있다.

다만 실제 착용 환경에서는 센서 안정화 시간이 필요하다.

권장 방식:

```text
1. 장치 착용 및 BLE 연결 완료
2. 첫 30초는 센서 안정화 시간으로 제외
3. 이후 60~120초 동안 HR / TEMP 수집
4. MPU6050 기준 움직임이 적은 구간만 사용
5. 비정상 튐 값 제거
6. 남은 값의 중앙값을 baselineHR, baselineTemp로 설정
```

계산 예시:

```text
baselineHR = median(stable HR samples)
deltaHR = currentHR - baselineHR

baselineTemp = median(stable TEMP samples)
deltaTemp = currentTemp - baselineTemp
```

## 9. 위험도 단계

Smart Shield는 위험도를 4단계로 구분한다.

| 단계 | 영문 값      | ESP32 명령         | 의미           |
| -- | --------- | ---------------- | ------------ |
| 정상 | SAFE      | `RISK:SAFE`      | 위험 징후 없음     |
| 주의 | CAUTION   | `RISK:CAUTION`   | 위험 가능성 증가    |
| 위험 | DANGER    | `RISK:DANGER`    | 위험 상태 가능성 높음 |
| 응급 | EMERGENCY | `RISK:EMERGENCY` | 즉시 확인 필요     |

---

## 10. Heat Stress Risk

Heat Stress Risk는 온열질환 위험 가능성을 판단하기 위한 점수이다.

### 사용 데이터

```text
ENV
HUM
LUX
TEMP
HR
ACTIVITY
```

### 판단 원칙

```text
1. 주변 온도가 높을수록 위험 가능성 증가
2. 주변 습도가 높을수록 위험 가능성 증가
3. 피부 접촉 온도가 baseline보다 지속적으로 상승하면 위험 가능성 증가
4. 심박수가 baseline보다 많이 상승하면 위험 가능성 증가
5. 활동량이 낮은데 심박수가 높으면 위험 가능성 증가
6. 활동량이 높은 상태의 심박 상승은 작업 강도 영향으로 일부 보정
7. 조도가 높으면 직사광선 노출 가능성으로 약하게 가중
```

### 좋은 판단 예시

```text
고온·고습 + 피부 접촉 온도 상승 + 활동량 대비 HR 과상승
→ 위험도 상승
```

### 나쁜 판단 예시

```text
HR > 120이면 무조건 위험
TEMP > 37.5이면 무조건 위험
SPO2가 낮으면 온열질환 위험
```

---

## 11. Abnormal State Risk

Abnormal State Risk는 온열질환과 별개로 낙상, 움직임 없음, 생체 신호 급변, BLE 연결 끊김 등을 판단하기 위한 점수이다.

### 사용 데이터

```text
POSTURE
ACTIVITY
HR 급변
SPO2 저하 플래그
BLE 연결 상태
```

### 판단 원칙

```text
1. POSTURE:FALL은 즉시 위험도 상승
2. POSTURE:EMERGENCY는 즉시 EMERGENCY 후보
3. 일정 시간 이상 움직임이 없으면 이상 상태 후보
4. HR이 갑자기 급상승 또는 급저하하면 이상 상태 후보
5. SpO2는 단독 판단하지 않고 응급 보조 플래그로 사용
6. BLE 장기 끊김은 상태 확인 필요 플래그로 사용
```

### 예시

```text
SpO2 저하 + 움직임 없음 + HR 이상
→ EMERGENCY 후보

SpO2만 낮고 손목 움직임이 심함
→ 측정 오류 가능성 우선
```

---

## 12. 즉시 EMERGENCY 후보 조건

다음 조건은 즉시 EMERGENCY 후보로 처리할 수 있다.

```text
POSTURE:EMERGENCY
POSTURE:FALL + 일정 시간 움직임 없음
SpO2 급저하 + 움직임 없음 + HR 이상
HR 급격한 비정상 변화 + 움직임 없음
위험 상태가 일정 시간 이상 지속
```

단, 센서값 신뢰도가 낮은 경우에는 즉시 확정하지 않고 재측정 또는 확인 필요 상태로 처리할 수 있다.

---

## 13. 센서 신뢰도 처리

센서값은 항상 신뢰할 수 있는 값으로 처리하지 않는다.

### HR / SpO2 신뢰도 낮음 조건

```text
손목 밴드가 헐거움
움직임이 큼
센서 접촉 상태가 불안정함
외부광 영향이 큼
HR이 갑자기 비정상적으로 튐
SpO2가 낮지만 움직임이 심함
```

처리:

```text
위험도 계산에서 제외
가중치 감소
이전 안정값 유지
재측정 필요 상태 표시
```

---

### TEMP 신뢰도 낮음 조건

```text
피부 접촉 센서가 피부에서 떨어짐
값이 갑자기 외기온과 비슷해짐
ESP32 또는 배터리 발열 영향을 받음
접촉 상태가 불안정함
```

처리:

```text
TEMP 가중치 감소
상승 추세가 일정 시간 이상 지속될 때만 반영
```

---

### LUX 신뢰도 낮음 조건

```text
센서가 옷이나 팔에 가려짐
RGB LED 빛이 직접 들어감
장치 방향이 계속 바뀜
```

처리:

```text
LUX는 보조 점수로만 사용
LUX 단독 위험 판단 금지
```

---

## 14. 위험도 산출 방식 예시

실제 구현에서는 점수 기반 또는 규칙 기반 방식을 사용할 수 있다.

예시 구조:

```text
heatStressScore = 환경 점수 + 피부온도 변화 점수 + 심박수 변화 점수 + 조도 보조 점수
abnormalScore = 자세 이상 점수 + 움직임 없음 점수 + 생체 신호 급변 점수 + BLE 끊김 점수

finalRisk = max(heatStressRisk, abnormalRisk)
```

위험도 결정 예시:

```text
0~29점: SAFE
30~59점: CAUTION
60~79점: DANGER
80점 이상: EMERGENCY
```

점수 기준은 실제 테스트 결과에 따라 조정한다.

---

## 15. 위험도 유지 및 완화

위험도는 센서값 하나가 순간적으로 튀었다고 바로 바뀌지 않도록 처리하는 것이 좋다.

권장 방식:

```text
CAUTION 이상은 일정 시간 유지
DANGER 이상은 더 강하게 유지
SAFE 복귀는 즉시가 아니라 안정 상태가 일정 시간 지속된 후 적용
센서 튐 값은 위험도 상승에서 제외
```

이렇게 하지 않으면 앱이 위험도를 초 단위로 뒤집는다. 사람도 그렇게 살면 피곤한데 앱까지 그러면 곤란하다.

## 17. ESP32 명령 매핑

위험도는 ESP32 제어 명령으로 변환된다.

| 위험도       | ESP32 명령         |
| --------- | ---------------- |
| SAFE      | `RISK:SAFE`      |
| CAUTION   | `RISK:CAUTION`   |
| DANGER    | `RISK:DANGER`    |
| EMERGENCY | `RISK:EMERGENCY` |

`RISK:ERROR`는 공식 위험도 명령이 아니다.

## 18. 검증 방법

위험도 알고리즘은 다음 조건에서 검증한다.

```text
정상 상태
고온·고습 상태
피부 접촉 온도 상승 상태
심박수 상승 상태
활동량 높음 + 심박수 상승 상태
활동량 낮음 + 심박수 상승 상태
낙상 후보 상태
움직임 없음 상태
SpO2 저하 + 움직임 없음 상태
BLE 연결 끊김 상태
센서값 누락 상태
센서값 튐 상태
```

## 19. 제한사항

본 알고리즘의 제한사항은 다음과 같다.

```text
의료 진단 불가
센서값 절대 정확도 보장 불가
손목 PPG 값은 움직임에 취약함
SpO2는 열스트레스 핵심 지표가 아님
피부 접촉 온도는 심부체온이 아님
조도값은 복사열이 아님
MPU6050만으로 낙상을 100% 확정할 수 없음
BLE 끊김은 통신 문제와 작업자 이상 상태를 구분하기 어려움
```

## 20. 최종 요약

Smart Shield 위험도 알고리즘은 작업자의 온열질환 위험 가능성과 이상 상태를 조기에 감지하기 위한 산업안전 보조 알고리즘이다.

위험도 계산은 Android 작업자 앱에서 수행하며, ESP32는 센서 데이터를 전송하고 위험도 명령에 따라 출력 장치를 제어한다.

위험도는 단일 센서값이 아니라 주변 온도, 습도, 조도, 피부 접촉 온도, 심박수, 산소포화도 보조 플래그, 자세 상태, 활동량, BLE 연결 상태를 종합하여 판단한다.

본 알고리즘은 의료 진단용이 아니며, 실제 현장 적용 전에는 충분한 센서 검증과 BLE 안정성 테스트가 필요하다.
