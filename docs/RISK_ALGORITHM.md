
# Smart Shield Risk Algorithm

## 1. 알고리즘 목적

Smart Shield의 위험도 알고리즘은 의료 진단이 아니라 산업안전 보조 목적의 위험 가능성 판단 로직이다.

따라서 센서값 하나만으로 질병이나 사고를 단정하지 않는다.  
주변 환경, 피부 접촉 온도 변화, 심박수 변화, 자세 상태, 움직임 상태, BLE 연결 상태를 함께 고려하여 작업자의 위험 가능성을 조기에 감지하는 것을 목표로 한다.

사용 가능한 표현:

```text
산업안전 보조 시스템
온열질환 위험 가능성 조기 감지
피부 접촉 온도 변화 추적
심박수 변화 기반 생리적 부담 추정
IMU 기반 자세 이상 및 낙상 가능성 추정
다중 센서 융합 기반 위험도 판단
````

피해야 할 표현:

```text
정확한 체온 측정
의료급 산소포화도 측정
온열질환 진단
낙상 100% 감지
SpO2 기반 열스트레스 판단
HR > 120이면 무조건 위험
TEMP > 37.5이면 무조건 위험
```

---

## 2. 위험도 단계

Smart Shield는 위험도를 4단계로 구분한다.

| 앱 표시 단계 | 의미                      | ESP32 전송 명령      |
| ------- | ----------------------- | ---------------- |
| 정상      | 특별한 이상 없음               | `RISK:SAFE`      |
| 주의      | 환경 또는 생체 변화 감지          | `RISK:CAUTION`   |
| 위험      | 복합 위험 조건 감지             | `RISK:DANGER`    |
| 응급      | 낙상, 심각한 이상 상태, 긴급 대응 필요 | `RISK:EMERGENCY` |

앱은 센서 데이터를 분석하여 위험도를 계산하고, 계산된 위험 단계에 따라 ESP32에 BLE Write 명령을 전송한다.

---

## 3. 입력 데이터

위험도 계산에는 다음 센서 데이터를 사용한다.

| 데이터              | 출처                     | 용도             |
| ---------------- | ---------------------- | -------------- |
| `TEMP`           | MAX30205 / Fever Click | 피부 접촉 온도 변화 추적 |
| `TEMP_VALID`     | ESP32 펌웨어              | 체온 센서값 유효 여부   |
| `TEMP_SOURCE`    | ESP32 펌웨어              | 체온 데이터 출처 구분   |
| `HR`             | MAX30102 / SEN0344     | 심박수 변화 추적      |
| `SPO2`           | MAX30102 / SEN0344     | 응급 보조 플래그      |
| `ENV`            | BME280                 | 주변 온도          |
| `HUM`            | BME280                 | 주변 습도          |
| `LUX`            | BH1750                 | 직사광선 노출 가능성 보조 |
| `AX`, `AY`, `AZ` | MPU6050                | 자세, 움직임, 충격 판단 |
| `POSTURE`        | ESP32 자세 판단 로직         | 자세 상태          |
| BLE RSSI         | Android BLE            | 연결 품질 보조 정보    |

---

## 4. 피부 접촉 온도 처리

MAX30205 / Fever Click은 심부체온을 직접 측정하는 의료기기가 아니다.
Smart Shield에서는 피부 접촉 온도의 절대값보다 작업 시작 후 기준값 대비 변화량과 지속 상승 추세를 위험 판단의 보조 지표로 사용한다.

현재 구현에서는 체온 센서값의 유효성을 `TEMP_VALID`, 데이터 출처를 `TEMP_SOURCE`로 함께 전달한다.

예시 payload:

```text
ID:0001,TEMP:34.8,TEMP_VALID:1,TEMP_SOURCE:MEASURED,HR:82,SPO2:98,ENV:28.4,HUM:55,LUX:1200,AX:0.01,AY:0.02,AZ:9.80,POSTURE:NORMAL
```

체온 센서값이 유효하지 않은 경우 앱은 해당 값을 핵심 위험 판단에 강하게 반영하지 않는다.

---

## 5. 심박수 처리

심박수는 온열 스트레스 또는 생리적 부담의 보조 지표로 사용한다.
단, 심박수는 작업 강도, 움직임, 긴장, 착용 상태에 따라 크게 달라질 수 있으므로 절대값 하나만으로 위험도를 단정하지 않는다.

현재 구현에서는 작업 시작 후 정상 자세 구간에서 확보된 초기 심박수를 기준값으로 사용한다.
향후 개선 방향으로는 작업 전 안정 구간에서 60~120초 동안 심박수를 수집하고, 튀는 값을 제거한 뒤 중앙값을 baselineHR로 사용하는 방식이 적절하다.

권장 해석:

```text
고온·고습 환경
+ 피부 접촉 온도 상승
+ 활동량 대비 심박수 과상승
→ 위험도 상승
```

피해야 할 해석:

```text
HR > 120이면 무조건 위험
```

---

## 6. SpO2 처리

SpO2는 온열질환 위험 판단의 핵심 지표로 사용하지 않는다.
손목 착용형 PPG 센서는 움직임, 압박, 외부광, 착용 상태에 민감하기 때문이다.

Smart Shield에서는 SpO2를 응급 상태 보조 플래그로만 사용한다.

예시:

```text
SpO2 저하 + 움직임 없음 + HR 이상 + 자세 이상
→ 응급 후보

SpO2만 낮고 손목 움직임이 큰 상태
→ 측정 오류 가능성 우선
```

---

## 7. 자세 및 움직임 처리

MPU6050의 `AX`, `AY`, `AZ` 값을 이용하여 움직임, 충격, 자세 이상 여부를 판단한다.

자세 상태는 다음 값을 사용한다.

| POSTURE 값   | 의미             |
| ----------- | -------------- |
| `NORMAL`    | 정상 자세          |
| `WARNING`   | 주의 자세          |
| `UNSTABLE`  | 불안정 자세         |
| `FALL`      | 낙상 후보          |
| `EMERGENCY` | 응급 자세 또는 이상 상태 |

낙상 후보 또는 응급 자세가 감지되면 열스트레스 점수와 별개로 위험도를 즉시 높일 수 있다.

---

## 8. 환경 데이터 처리

BME280의 주변 온도 `ENV`, 습도 `HUM`은 온열 위험 가능성을 판단하는 핵심 환경 데이터로 사용한다.

BH1750의 `LUX`는 열을 직접 측정하는 값이 아니라 조도값이다.
따라서 직사광선 노출 가능성을 보조적으로 추정하는 데만 사용한다.

주의:

```text
LUX는 복사열 또는 체감온도를 직접 의미하지 않는다.
LUX 단독으로 위험도를 올리지 않는다.
```

---

## 9. BLE 연결 상태 처리

BLE RSSI와 연결 상태는 센서값의 신뢰도와 작업자 상태 확인 가능성을 판단하는 보조 정보이다.

앱에서는 BLE 신호 상태를 다음과 같이 표시한다.

| 표시값  | 의미        |
| ---- | --------- |
| 좋음   | 안정적인 연결   |
| 보통   | 사용 가능한 연결 |
| 약함   | 끊김 가능성 있음 |
| 끊김   | BLE 연결 끊김 |
| 연결 전 | 아직 연결 전   |

BLE 연결이 장시간 끊긴 경우 작업자 상태 확인이 어려우므로 관리자 앱에서 확인이 필요한 상태로 표시할 수 있다.

---

## 10. ESP32 출력 제어

최종 시연 버전에서는 RGB LED 대신 단일 RED LED를 사용한다.

ESP32는 앱에서 수신한 위험도 명령에 따라 다음 출력 장치를 제어한다.

| 출력 장치   | 역할          |
| ------- | ----------- |
| RED LED | 위험 단계 시각 표시 |
| 진동모터    | 작업자 촉각 경고   |
| 부저      | 작업자 청각 경고   |

위험도별 출력은 RED LED 점등/점멸, 진동 패턴, 부저 패턴을 조합하여 표현한다.

기존 문서의 RGB LED 색상 표현은 최종 코드 기준과 다르므로 사용하지 않는다.
