
# Smart Shield Test Plan

## 1. 테스트 목적

본 테스트 계획은 Smart Shield 최종 발표 전 다음 항목을 검증하기 위한 문서이다.

- ESP32 센서 수집 정상 동작
- BLE Notify 수신 정상 동작
- Android 작업자 앱 payload 파싱 정상 동작
- 위험도 계산 및 ESP32 Write 명령 전송 정상 동작
- RED LED, 진동모터, 부저 출력 정상 동작
- Firebase currentStatus 및 riskLogs 업로드 정상 동작
- 관리자 앱 Firebase 조회 및 상태 표시 정상 동작

---

## 2. ESP32 센서 테스트

| 항목 | 확인 내용 | 기대 결과 |
|---|---|---|
| I2C Scanner | 센서 주소 확인 | 필요한 센서 주소가 스캔됨 |
| BME280 | 주변 온도, 습도 측정 | `ENV`, `HUM` 값 출력 |
| BH1750 | 조도 측정 | `LUX` 값 출력 |
| MPU6050 | 가속도 측정 | `AX`, `AY`, `AZ` 값 출력 |
| MAX30102 | 심박수, SpO2 추정 | `HR`, `SPO2` 값 출력 |
| MAX30205 | 피부 접촉 온도 측정 | `TEMP`, `TEMP_VALID`, `TEMP_SOURCE` 출력 |

MAX30205 / Fever Click은 최종 통합 펌웨어 기준으로 `0x48` 주소를 사용한다.  
다른 주소가 I2C Scanner에서 확인되는 경우 펌웨어 상수 수정이 필요하다.

---

## 3. BLE 테스트

| 항목 | 확인 내용 | 기대 결과 |
|---|---|---|
| BLE 광고명 | ESP32 광고명 확인 | `SS_0001` 형식 |
| Service UUID | 앱과 ESP32 UUID 일치 확인 | 동일 UUID로 연결 |
| Notify | ESP32 → 앱 센서 데이터 전송 | 앱에서 payload 수신 |
| Write | 앱 → ESP32 위험도 명령 전송 | ESP32가 명령 수신 |
| RSSI | BLE 신호 세기 표시 | 좋음/보통/약함/끊김 표시 |
| 재연결 | 연결 끊김 후 재시도 | 일정 시간 내 재연결 시도 |

---

## 4. BLE Payload 테스트

예상 payload:

```text
ID:0001,TEMP:34.8,TEMP_VALID:1,TEMP_SOURCE:MEASURED,HR:82,SPO2:98,ENV:28.4,HUM:55,LUX:1200,AX:0.01,AY:0.02,AZ:9.80,POSTURE:NORMAL
````

| 필드               | 확인 내용                       |
| ---------------- | --------------------------- |
| `ID`             | Firebase workerId와 일치하는지 확인 |
| `TEMP`           | 온도값 파싱 여부 확인                |
| `TEMP_VALID`     | 유효 플래그 파싱 여부 확인             |
| `TEMP_SOURCE`    | 데이터 출처 파싱 여부 확인             |
| `HR`             | 심박수 파싱 여부 확인                |
| `SPO2`           | SpO2 파싱 여부 확인               |
| `ENV`            | 주변 온도 파싱 여부 확인              |
| `HUM`            | 습도 파싱 여부 확인                 |
| `LUX`            | 조도 파싱 여부 확인                 |
| `AX`, `AY`, `AZ` | 가속도값 파싱 여부 확인               |
| `POSTURE`        | 자세 상태 파싱 여부 확인              |

## 5. 위험도 명령 테스트

| 앱 위험도 | ESP32 명령         | 기대 출력                |
| ----- | ---------------- | -------------------- |
| 정상    | `RISK:SAFE`      | 경고 출력 없음 또는 최소 상태    |
| 주의    | `RISK:CAUTION`   | 약한 경고 패턴             |
| 위험    | `RISK:DANGER`    | RED LED, 진동모터, 부저 경고 |
| 응급    | `RISK:EMERGENCY` | 강한 경고 패턴 또는 반복 경고    |

최종 시연 버전은 RGB LED가 아니라 단일 RED LED를 사용한다.
따라서 RGB 색상 전환 테스트가 아니라 RED LED 점등/점멸 테스트를 수행한다.

## 6. Firebase 테스트

| 항목                 | 확인 내용                  | 기대 결과                              |
| ------------------ | ---------------------- | ---------------------------------- |
| currentStatus 업로드  | 최신 상태 저장               | `workers/0001/currentStatus` 갱신    |
| riskLogs 업로드       | 위험 이벤트 저장              | `workers/0001/riskLogs/{logId}` 생성 |
| workerId 일치        | BLE ID와 Firebase 경로 비교 | `SS_0001` → `0001`                 |
| riskLevel 저장값      | 한글 위험도 저장 확인           | `정상`, `주의`, `위험`, `응급`             |
| bleSignalLevel 저장값 | 한글 신호 상태 저장 확인         | `좋음`, `보통`, `약함`, `끊김`, `연결 전`     |
| 작업 위치 저장값          | 최종 위치 코드 확인            | `LOC_ROOF` 등 최종 코드값 저장             |

기존 문서의 `ZONE_A`, `A구역`, `CAUTION`, `GOOD` 같은 예시는 최종 코드 기준과 다르므로 테스트 기준으로 사용하지 않는다.

---

## 7. 관리자 앱 테스트

| 항목          | 확인 내용                   | 기대 결과           |
| ----------- | ----------------------- | --------------- |
| Firebase 연결 | DB 조회 가능 여부             | 작업자 목록 표시       |
| 작업자 목록      | currentStatus 표시        | 최신 상태 반영        |
| 위험 작업자 표시   | 위험도 높은 작업자 확인           | 위험 작업자 우선 확인 가능 |
| 상세 화면       | 개별 작업자 상세 정보 표시         | 센서값, 위험도, 위치 표시 |
| 갱신 방식       | 주기 갱신 및 Firebase 리스너 확인 | 최신 상태가 화면에 반영   |

관리자 앱은 BLE 기능을 수행하지 않는다.
관리자 앱은 Firebase 데이터를 읽어 작업자 상태를 모니터링한다.

---

## 8. 발표 전 최종 시연 테스트 순서

```text
1. ESP32 전원 인가
2. Serial Monitor에서 센서 초기화 상태 확인
3. Android 작업자 앱 실행
4. 작업 위치 선택
5. BLE 장치 SS_0001 검색 및 연결
6. BLE Notify payload 수신 확인
7. 앱 메인 화면 센서값 표시 확인
8. 위험도 계산 결과 확인
9. ESP32 RED LED, 진동모터, 부저 출력 확인
10. Firebase currentStatus 갱신 확인
11. 위험 상황 발생 시 riskLogs 생성 확인
12. 관리자 앱에서 작업자 상태 표시 확인
13. BLE 끊김 후 재연결 또는 끊김 상태 표시 확인
```

---

## 9. 최종 판정 기준

발표 전 최소 통과 기준은 다음과 같다.

| 영역       | 최소 통과 기준                       |
| -------- | ------------------------------ |
| ESP32    | 센서값이 Serial Monitor에 출력됨       |
| BLE      | 작업자 앱에서 `SS_0001` 연결 가능        |
| Payload  | 앱에서 센서값 파싱 가능                  |
| 위험도      | 정상/주의/위험/응급 중 하나로 표시 가능        |
| 출력       | RED LED, 진동모터, 부저 중 위험도별 출력 확인 |
| Firebase | currentStatus 갱신 확인            |
| 관리자 앱    | Firebase 기반 작업자 상태 확인 가능       |

위 항목 중 하나라도 실패하면 발표에서는 해당 기능을 “추가 검증 필요”로 표현한다.
