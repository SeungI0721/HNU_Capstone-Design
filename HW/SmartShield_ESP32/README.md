
# SmartShield_ESP32

## 1. 폴더 개요

이 폴더는 Smart Shield 프로젝트의 ESP32 최종 통합 펌웨어를 포함한다.

ESP32는 웨어러블 장치의 중심 보드로 동작하며, 센서 데이터를 수집하고 Android 작업자 앱과 BLE로 통신한다. 또한 작업자 앱에서 계산한 위험도 명령을 BLE Write로 수신하여 RGB LED, 진동모터, 부저를 제어한다.

> 본 펌웨어는 의료 진단 장치용 코드가 아니다.  
> 센서값은 작업자의 온열질환 위험 가능성과 이상 상태를 조기에 감지하기 위한 산업안전 보조 데이터로 사용한다.

---

## 2. 주요 역할

ESP32 펌웨어의 주요 역할은 다음과 같다.

```text
1. 센서 데이터 수집
2. 센서값 보정 및 기본값 처리
3. BLE Peripheral / GATT Server 동작
4. Android 작업자 앱으로 BLE Notify 전송
5. Android 작업자 앱에서 BLE Write 명령 수신
6. 위험도 명령에 따라 RGB LED / 진동모터 / 부저 제어
7. 시리얼 로그를 통한 디버깅 지원
````

## 7. I2C 센서 주소

| 센서                     | 예상 주소               | 비고                                   |
| ---------------------- | ------------------- | ------------------------------------ |
| BME280                 | `0x76` 또는 `0x77`    | 모듈 SDO 설정에 따라 달라질 수 있음               |
| BH1750 / GY-302        | `0x23` 또는 `0x5C`    | ADDR 핀 상태에 따라 달라질 수 있음               |
| MPU6050 / GY-521       | 보통 `0x68`           | AD0 상태에 따라 `0x69` 가능                 |
| MAX30102 / SEN0344     | `0x57`              | SEN0344 V2.0 기준                      |
| MAX30205 / Fever Click | `0x49` 예상, 실물 확인 필요 | 보드 배선에 따라 달라질 수 있으므로 I2C Scanner로 확인 |

> MAX30205 / Fever Click의 주소는 실물 보드 배선에 따라 달라질 수 있다.
> 코드에서 `0x48` 또는 `0x49`를 사용하는 경우, 반드시 I2C Scanner 결과와 일치하는지 확인한다.

## 8. BLE 통신 구조

ESP32는 BLE Peripheral / GATT Server로 동작한다.

Android 작업자 앱은 BLE Central / GATT Client로 동작한다.

```text
ESP32 센서값 수집
→ BLE Notify
→ Android 작업자 앱 수신
→ 작업자 앱에서 위험도 계산
→ BLE Write로 ESP32에 위험도 명령 전송
→ ESP32 출력 장치 제어
```

---

## 9. BLE 이름 규칙

ESP32 BLE 장치 이름은 다음 형식을 사용한다.

```text
SS_0001
```

작업자 ID는 BLE 이름, 센서 payload, Firebase 경로에서 동일하게 사용한다.

```text
BLE Device Name: SS_0001
Sensor Payload ID: 0001
Firebase workerId: 0001
```

## 11. BLE Notify Payload

ESP32는 센서 데이터를 문자열 payload로 구성하여 Android 작업자 앱에 Notify로 전송한다.

### 기본 payload 예시

```text
ID:0001,TEMP:36.5,HR:102,SPO2:97,ENV:33.1,HUM:71,LUX:45000,AX:0.12,AY:-0.08,AZ:9.78,POSTURE:NORMAL
```

### 필드 설명

| 필드        | 의미        | 예시       |
| --------- | --------- | -------- |
| `ID`      | 작업자 ID    | `0001`   |
| `TEMP`    | 피부 접촉 온도  | `36.5`   |
| `HR`      | 심박수 추정값   | `102`    |
| `SPO2`    | 산소포화도 추정값 | `97`     |
| `ENV`     | 주변 온도     | `33.1`   |
| `HUM`     | 주변 습도     | `71`     |
| `LUX`     | 조도        | `45000`  |
| `AX`      | X축 가속도    | `0.12`   |
| `AY`      | Y축 가속도    | `-0.08`  |
| `AZ`      | Z축 가속도    | `9.78`   |
| `POSTURE` | 자세 상태     | `NORMAL` |

### POSTURE 값

```text
NORMAL
WARNING
UNSTABLE
FALL
EMERGENCY
```

## 12. BLE Write 명령

Android 작업자 앱은 위험도 계산 결과를 ESP32로 전송한다.

공식 위험도 명령은 다음 4개이다.

```text
RISK:SAFE
RISK:CAUTION
RISK:DANGER
RISK:EMERGENCY
```

| 명령               | 의미 | ESP32 출력                      |
| ---------------- | -- | ----------------------------- |
| `RISK:SAFE`      | 정상 | LED 초록, 진동 OFF, 부저 OFF        |
| `RISK:CAUTION`   | 주의 | LED 노랑, 짧은 진동, 짧은 부저          |
| `RISK:DANGER`    | 위험 | LED 빨강, 반복 진동, 반복 부저          |
| `RISK:EMERGENCY` | 응급 | LED 빨강 점멸, 강한 반복 진동, 빠른 반복 부저 |

### 오류 처리

`RISK:ERROR`는 공식 위험 단계가 아니다.

`RISK:ERROR`는 다음 상황에서만 보조 상태로 사용할 수 있다.

```text
1. 알 수 없는 BLE Write 명령 수신
2. 센서값 파싱 실패
3. 내부 상태 오류
4. 디버깅용 예외 처리
```

최종 앱과 ESP32 사이의 공식 프로토콜은 `SAFE`, `CAUTION`, `DANGER`, `EMERGENCY` 4단계를 기준으로 한다.

## 13. 위험도 출력 기준

ESP32는 위험도를 직접 계산하지 않고, Android 작업자 앱에서 계산한 위험도 명령을 수신하여 출력 장치를 제어한다.

```text
Android 작업자 앱: 위험도 계산
ESP32: 위험도 명령 수신 후 출력 제어
```

| 위험도       | LED   | 진동모터     | 부저       |
| --------- | ----- | -------- | -------- |
| SAFE      | 초록    | OFF      | OFF      |
| CAUTION   | 노랑    | 짧은 진동 1회 | 짧은 부저 1회 |
| DANGER    | 빨강    | 반복 진동    | 느린 반복 부저 |
| EMERGENCY | 빨강 점멸 | 강한 반복 진동 | 빠른 반복 부저 |

## 14. 센서 데이터 처리 기준

### 14-1. BME280

BME280은 주변 환경 데이터를 측정한다.

사용 필드:

```text
ENV
HUM
PRESS
```

주의:

* 주변 온도와 습도는 온열질환 위험 가능성 판단의 환경 조건으로 사용한다.
* BME280은 피부 온도나 체온을 측정하지 않는다.
* ESP32, 배터리, 손열 등 주변 발열 영향을 줄여야 한다.

---

### 14-2. BH1750 / GY-302

BH1750은 조도를 측정한다.

사용 필드:

```text
LUX
```

주의:

* BH1750은 복사열 센서가 아니다.
* 조도값은 직사광선 노출 가능성을 추정하는 보조 지표이다.
* 조도값만으로 위험도를 단정하지 않는다.
* RGB LED 빛이 BH1750에 직접 들어가지 않도록 배치한다.

---

### 14-3. MPU6050 / GY-521

MPU6050은 자세와 움직임을 추정하는 데 사용한다.

사용 필드:

```text
AX
AY
AZ
POSTURE
```

주의:

* MPU6050만으로 낙상을 확정하지 않는다.
* 큰 가속도 변화, 자세 변화, 이후 움직임 없음 등을 함께 고려해야 한다.
* Android 작업자 앱에서 활동량과 자세 상태를 위험도 계산에 활용한다.

---

### 14-4. MAX30102 / SEN0344

MAX30102 / SEN0344는 심박수와 산소포화도 추정값을 제공한다.

사용 필드:

```text
HR
SPO2
```

주의:

* 손목 착용 시 움직임, 압박, 외부광에 민감하다.
* HR은 절대값보다 개인 기준 대비 변화량을 중심으로 해석한다.
* SpO2는 열스트레스 핵심 지표가 아니라 응급 보조 플래그로만 사용한다.
* SpO2 단독으로 위험도를 올리지 않는다.

---

### 14-5. MAX30205 / Fever Click

MAX30205 / Fever Click은 피부 접촉 온도 변화를 추적한다.

사용 필드:

```text
TEMP
```

주의:

* 심부체온을 직접 측정하지 않는다.
* 피부 접촉 온도 변화 추적용 보조 센서이다.
* 센서 밀착 상태, 땀, 의복 압박, 외부 열원에 영향을 받을 수 있다.
* 절대값보다 baseline 대비 변화량과 지속 상승 추세가 중요하다.

## 15. 센서 기본값 및 fallback 처리

센서가 연결되지 않았거나 측정값이 불안정할 경우, 펌웨어는 테스트 또는 디버깅을 위해 fallback 값을 사용할 수 있다.

fallback 값은 실제 측정값이 아니다.

README, 발표 자료, 보고서에서는 fallback 값을 실제 센서 측정 결과처럼 표현하지 않는다.

예시:

```text
MAX30102 미검출 → HR/SPO2 fallback 사용 가능
MAX30205 미검출 → TEMP fallback 사용 가능
```

권장 표현:

```text
센서 미연결 또는 측정 실패 시 테스트용 기본값을 사용한다.
```

피해야 할 표현:

```text
센서가 없어도 정상 측정된다.
```

이건 거짓말이다. 코드가 착한 척하는 것뿐이다.

## 16. BLE 전송 주기

Smart Shield는 온열질환 위험 가능성, 피부 접촉 온도 변화, 심박수 추세, 자세 이상을 확인하는 시스템이다.

따라서 초고속 스트리밍보다 안정적인 수신이 중요하다.

권장 전송 주기:

| 구분          | 주기             |
| ----------- | -------------- |
| 초기 안정 구현    | 500ms ~ 1000ms |
| 실시간성 개선 후   | 100ms ~ 200ms  |
| 고속 스트리밍 실험용 | 35ms           |
| 검증 전 비권장    | 25ms 이하        |

최종 캡스톤 구현에서는 1초 주기 전송도 충분히 실용적이다.

## 21. 전원 및 배선 주의사항

* ESP32와 모든 센서는 GND를 공통으로 연결한다.
* I2C 센서는 기본적으로 3.3V 기준으로 연결한다.
* 5V 모듈 사용 시 SDA/SCL 풀업 전압을 반드시 확인한다.
* 진동모터는 ESP32 GPIO에 직접 연결하지 않는다.
* 진동모터 구동 시 MOSFET 또는 트랜지스터를 사용한다.
* 모터 사용 시 플라이백 다이오드를 권장한다.
* 긴 점퍼선은 I2C 통신 불안정의 원인이 될 수 있다.
* 배터리, ESP32, 온도 센서는 열적으로 최대한 분리한다.
* MAX30205는 피부 접촉 온도 센서이므로 ESP32 발열 영향을 받지 않도록 배치한다.

## 24. 최종 요약

`SmartShield_ESP32` 폴더는 Smart Shield의 ESP32 최종 통합 펌웨어를 관리한다.

ESP32는 BME280, BH1750, MPU6050, MAX30102 / SEN0344, MAX30205 / Fever Click 센서 데이터를 수집하고, BLE Notify를 통해 Android 작업자 앱으로 전송한다.

Android 작업자 앱은 수신 데이터를 기반으로 위험도를 계산하고, BLE Write로 ESP32에 `RISK:SAFE`, `RISK:CAUTION`, `RISK:DANGER`, `RISK:EMERGENCY` 명령을 전송한다.

ESP32는 수신한 위험도 명령에 따라 RGB LED, 진동모터, 부저를 제어한다.

본 펌웨어는 의료 진단용이 아니라, 작업자의 온열질환 위험 가능성과 이상 상태를 조기에 감지하고 경고하기 위한 산업안전 보조 시스템의 일부이다.
