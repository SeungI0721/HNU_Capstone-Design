
# Smart Shield HW

## 1. 폴더 개요

이 폴더는 Smart Shield 프로젝트의 하드웨어 관련 소스와 테스트 코드를 포함한다.

Smart Shield 하드웨어는 ESP32 DevKit을 중심으로 여러 센서를 연결하여 작업자의 환경 데이터, 생체 신호, 자세 및 움직임 데이터를 수집하고, BLE를 통해 Android 작업자 앱으로 전송한다.

또한 Android 작업자 앱에서 계산한 위험도 명령을 BLE Write로 수신하여 RGB LED, 진동모터, 부저를 제어한다.

> 본 하드웨어는 의료 진단 장치가 아니다.  
> 센서값은 작업자의 위험 가능성을 조기에 감지하기 위한 보조 데이터로 사용한다.

| I2C SDA   | GPIO21      | BME280, BH1750, MPU6050, MAX30102, MAX30205  |

## 7. I2C 센서 주소 기준

| 센서                     | 예상 주소               | 비고                                   |
| ---------------------- | ------------------- | ------------------------------------ |
| BME280                 | `0x76` 또는 `0x77`    | 모듈 SDO 설정에 따라 달라질 수 있음               |
| BH1750 / GY-302        | `0x23` 또는 `0x5C`    | ADDR 핀 상태에 따라 달라질 수 있음               |
| MPU6050 / GY-521       | 보통 `0x68`           | AD0 상태에 따라 `0x69` 가능                 |
| MAX30102 / SEN0344     | `0x57`              | SEN0344 V2.0 기준                      |
| MAX30205 / Fever Click | `0x49` 예상, 실물 확인 필요 | 보드 배선에 따라 달라질 수 있으므로 I2C Scanner로 확인 |

> 최종 연결 전 반드시 I2C Scanner로 실제 주소를 확인한다.
> 문서보다 스캐너가 우선이다. 전자부품은 사람의 기대를 배신하는 데 재능이 있다.

## 8. BLE 통신 구조

Smart Shield의 ESP32는 BLE Peripheral / GATT Server로 동작한다.

Android 작업자 앱은 BLE Central / GATT Client로 동작한다.

```text
ESP32 센서값 수집
→ BLE Notify
→ Android 작업자 앱 수신
→ 위험도 계산
→ BLE Write
→ ESP32 출력 장치 제어
```

---

## 9. BLE 이름 규칙

ESP32 BLE 장치 이름은 다음 형식을 사용한다.

```text
SS_0001
```

작업자 ID는 BLE 이름, 센서 payload, Firebase 경로에서 동일하게 사용한다.

```text
BLE Device Name: SS_0001
Sensor Payload ID: 0001
Firebase workerId: 0001
```

## 11. BLE Notify Payload 예시

ESP32는 센서 데이터를 문자열 payload로 구성하여 작업자 앱에 Notify로 전송한다.

```text
ID:0001,TEMP:36.5,HR:102,SPO2:97,ENV:33.1,HUM:71,LUX:45000,AX:0.12,AY:-0.08,AZ:9.78,POSTURE:NORMAL
```

### 주요 필드

| 필드        | 의미        |
| --------- | --------- |
| `ID`      | 작업자 ID    |
| `TEMP`    | 피부 접촉 온도  |
| `HR`      | 심박수       |
| `SPO2`    | 산소포화도 추정값 |
| `ENV`     | 주변 온도     |
| `HUM`     | 주변 습도     |
| `LUX`     | 조도        |
| `AX`      | X축 가속도    |
| `AY`      | Y축 가속도    |
| `AZ`      | Z축 가속도    |
| `POSTURE` | 자세 상태     |

## 12. BLE Write 명령

Android 작업자 앱은 위험도 계산 결과를 ESP32로 전송한다.

공식 위험도 명령은 다음 4개이다.

```text
RISK:SAFE
RISK:CAUTION
RISK:DANGER
RISK:EMERGENCY
```

| 명령               | 의미 | ESP32 출력                |
| ---------------- | -- | ----------------------- |
| `RISK:SAFE`      | 정상 | LED 초록, 진동 OFF, 부저 OFF  |
| `RISK:CAUTION`   | 주의 | LED 노랑, 짧은 진동, 짧은 부저    |
| `RISK:DANGER`    | 위험 | LED 빨강, 반복 진동, 반복 부저    |
| `RISK:EMERGENCY` | 응급 | LED 빨강 점멸, 강한 진동, 빠른 부저 |

`RISK:ERROR`와 같은 값은 공식 위험 단계가 아니라, 알 수 없는 명령 또는 내부 오류 처리용 보조 상태로만 사용한다.

## 13. 센서별 역할

### 13-1. BME280

BME280은 주변 환경 조건을 측정한다.

사용 데이터:

```text
ENV
HUM
PRESS
```

활용:

* 주변 온도 확인
* 주변 습도 확인
* 온열질환 위험 가능성 판단의 환경 조건으로 사용

주의:

* BME280은 피부 온도를 측정하지 않는다.
* ESP32, 배터리, 손열 등 주변 발열 영향을 줄여야 한다.

---

### 13-2. BH1750 / GY-302

BH1750은 조도를 측정한다.

사용 데이터:

```text
LUX
```

활용:

* 직사광선 노출 가능성 보조 판단
* 그늘 / 밝은 환경 여부 추정

주의:

* BH1750은 복사열 센서가 아니다.
* 조도값만으로 온열질환 위험도를 단정하지 않는다.
* RGB LED 빛이 센서에 직접 들어가지 않도록 배치한다.

---

### 13-3. MPU6050 / GY-521

MPU6050은 3축 가속도와 3축 자이로 데이터를 측정한다.

사용 데이터:

```text
AX
AY
AZ
POSTURE
```

활용:

* 자세 변화 감지
* 움직임 없음 감지
* 낙상 가능성 추정
* 심박수 해석 시 활동량 보정

주의:

* MPU6050 하나만으로 낙상을 확정하지 않는다.
* 큰 충격, 자세 변화, 이후 움직임 없음 등을 함께 판단해야 한다.

---

### 13-4. MAX30102 / SEN0344

MAX30102 / SEN0344는 심박수와 산소포화도 추정값을 제공한다.

사용 데이터:

```text
HR
SPO2
```

활용:

* 심박수 변화 기반 생리적 부담 추정
* SpO2 저하 시 응급 보조 플래그로 사용

주의:

* 손목 착용 시 움직임, 압박, 외부광에 민감하다.
* HR은 절대값보다 baseline 대비 변화량을 사용한다.
* SpO2는 열스트레스 핵심 지표가 아니라 응급 보조 플래그로만 사용한다.
* SpO2 단독으로 위험도를 올리지 않는다.

---

### 13-5. MAX30205 / Fever Click

MAX30205 / Fever Click은 피부 접촉 온도 변화를 추적한다.

사용 데이터:

```text
TEMP
```

활용:

* 피부 접촉 온도 변화 추적
* baseline 대비 상승량 확인
* 온열질환 위험 가능성 판단의 보조 지표

주의:

* 심부체온을 직접 측정하지 않는다.
* 피부 접촉 상태, 땀, 의복 압박, 센서 밀착 상태에 영향을 받는다.
* 절대값보다 변화 추세를 중심으로 사용한다.

## 14. 출력 장치 역할

### 14-1. RGB LED

위험도 단계에 따라 색상을 표시한다.

| 단계        | 색상    |
| --------- | ----- |
| SAFE      | 초록    |
| CAUTION   | 노랑    |
| DANGER    | 빨강    |
| EMERGENCY | 빨강 점멸 |

---

### 14-2. 진동모터

작업자에게 촉각 경고를 제공한다.

주의:

* ESP32 GPIO에 직접 연결하지 않는다.
* MOSFET 또는 트랜지스터를 사용해 구동한다.
* 플라이백 다이오드 사용을 권장한다.

---

### 14-3. Buzzer

작업자에게 청각 경고를 제공한다.

주의:

* Active Buzzer는 ON/OFF 제어 중심으로 사용한다.
* Passive Buzzer는 PWM 제어가 필요하다.
* 실제 사용 환경에서는 부저 소리가 너무 작거나 너무 클 수 있으므로 테스트가 필요하다.

## 16. BLE 위치별 안정성 테스트

BLE 성능은 휴대폰 위치, 착용 위치, 인체 차폐, 장애물, 휴대폰 기종에 영향을 받는다.

따라서 다음 조건을 테스트한다.

| 조건           | 확인 항목            |
| ------------ | ---------------- |
| 휴대폰 손에 든 상태  | RSSI, Notify 수신률 |
| 휴대폰 앞주머니     | 수신 안정성           |
| 휴대폰 뒷주머니     | 인체 차폐 영향         |
| 휴대폰 가방 안     | 장애물 영향           |
| 휴대폰 책상 위     | 기준선 성능           |
| ESP32와 같은 몸쪽 | 수신 안정성           |
| ESP32와 반대 몸쪽 | 몸통 차폐 영향         |
| 걷기 / 팔 움직임   | 움직임 중 누락 여부      |

기록 항목:

```text
RSSI
BLE 연결 상태
Notify 수신 성공률
1분당 누락 패킷 수
연결 끊김 횟수
재연결 성공 시간
마지막 데이터 수신 시각
휴대폰 위치
작업자 자세
```

## 17. 전원 및 배선 주의사항

* ESP32와 모든 센서는 GND를 공통으로 연결한다.
* I2C 센서는 기본적으로 3.3V 기준으로 연결한다.
* 5V 모듈을 사용할 경우 SDA/SCL 풀업 전압을 반드시 확인한다.
* 진동모터는 ESP32 GPIO에 직접 연결하지 않는다.
* 모터 구동 시 MOSFET 또는 트랜지스터를 사용한다.
* 긴 점퍼선은 I2C 통신 불안정의 원인이 될 수 있다.
* 센서가 인식되지 않으면 먼저 I2C Scanner로 주소를 확인한다.
* 여러 I2C 모듈을 동시에 연결할 때 주소 충돌 여부를 확인한다.

## 20. 최종 요약

`HW` 폴더는 Smart Shield의 ESP32 웨어러블 장치와 하드웨어 테스트 코드를 관리한다.

최종 하드웨어는 ESP32 DevKit, BME280, BH1750, MPU6050, MAX30102 / SEN0344, MAX30205 / Fever Click, RGB LED, 진동모터, 부저로 구성된다.

ESP32는 센서 데이터를 수집하여 BLE Notify로 Android 작업자 앱에 전송하고, 작업자 앱에서 계산한 위험도 명령을 BLE Write로 수신하여 출력 장치를 제어한다.

하드웨어 검증은 센서 단독 테스트, 출력 장치 단독 테스트, BLE 통신 테스트, Android 앱 연동 테스트 순서로 진행한다.
