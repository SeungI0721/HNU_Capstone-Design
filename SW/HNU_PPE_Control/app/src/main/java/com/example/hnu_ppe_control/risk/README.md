# Risk 알고리즘 흐름

이 폴더는 ESP32에서 받은 센서 데이터를 앱 공통 위험 단계(`RiskLevel`)로 변환하고, 최종적으로 ESP32에 다시 보낼 `RISK:*` BLE 명령을 만드는 역할을 합니다.

## 주요 파일

| 파일 | 역할 |
|---|---|
| `HeatstrokeAnalyzer.kt` | 센서값을 점수화해 `SAFE`, `CAUTION`, `DANGER`, `EMERGENCY` 중 하나를 산출 |
| `RiskCommandMapper.kt` | `RiskLevel`을 ESP32 제어 명령 문자열(`RISK:*`)로 변환 |

## 입력 데이터

`HeatstrokeAnalyzer.analyze()`는 `SensorData`와 작업 시작 직후 측정한 기준 심박수(`baselineHR`)를 입력으로 받습니다.

사용하는 주요 센서값은 다음과 같습니다.

| 값 | 용도 |
|---|---|
| `ax`, `ay`, `az` | 움직임 여부와 격렬한 활동 여부 판단 |
| `hr` | 기준 심박수 대비 증가량 계산 |
| `spo2` | 응급 바이패스 조건 판단 |
| `env`, `hum` | 온습도 기반 체감 위험 점수 계산 |
| `lux` | 직사광선 노출 가능성 점수 계산 |
| `temp` | 절대 체온 기반 위험 점수 계산 |

## 분석 순서

1. 가속도 SVM 계산
   - `sqrt(ax^2 + ay^2 + az^2)`로 움직임 강도를 계산합니다.
   - SVM이 중력가속도 9.8 근처이면 정지 상태로 봅니다.

2. 무반응 시간 점수
   - 정지 상태가 지속되면 `motionStartTime`을 기준으로 누적 시간을 계산합니다.
   - 10초 이상: 10점
   - 20초 이상: 20점
   - 30초 이상: 40점, 무반응 상태로 확정
   - 움직임이 다시 감지되면 타이머를 초기화합니다.

3. 심박수 점수
   - 최근 5개 심박수를 이동 평균으로 계산합니다.
   - 기준 심박수 대비 증가량(`deltaHr`)을 봅니다.
   - +20 이상: 10점
   - +30 이상: 25점
   - +50 이상: 40점
   - 단, 움직임이 크고 정지 상태가 아니면 노동 중 심박 상승으로 보고 점수를 절반으로 낮춥니다.

4. 온습도 점수
   - `heatIndex = env + hum * 0.1`로 간단한 체감 위험 지수를 계산합니다.
   - 33 이상: 5점
   - 35 이상: 10점
   - 38 이상: 20점

5. 조도 점수
   - 30,000 lux 이상: 5점
   - 50,000 lux 이상: 15점

6. 체온 점수
   - 체온이 35.0~42.0 범위일 때만 위험 점수에 반영합니다.
   - 38.0도 이상: 15점
   - 39.0도 이상: 30점

7. 응급 바이패스
   - 산소포화도가 84 이하로 5초 이상 지속되고, 동시에 30초 이상 무반응이면 즉시 `EMERGENCY`를 반환합니다.
   - 이 조건은 누적 점수보다 우선합니다.

8. 최종 위험 단계 결정
   - 총점 0~29: `SAFE`
   - 총점 30~59: `CAUTION`
   - 총점 60 이상: `DANGER`
   - 응급 바이패스 충족: `EMERGENCY`

## BLE 명령 변환

`RiskCommandMapper.toCommand()`는 앱의 위험 단계를 ESP32 출력 제어 명령으로 변환합니다.

| RiskLevel | BLE 명령 |
|---|---|
| `SAFE` | `RISK:SAFE` |
| `CAUTION` | `RISK:CAUTION` |
| `DANGER` | `RISK:DANGER` |
| `EMERGENCY` | `RISK:EMERGENCY` |
| `ERROR` | `RISK:SAFE` |

ESP32는 이 명령을 받아 LED, 진동 모터, 부저 출력을 제어합니다.

## 상태 초기화

`HeatstrokeAnalyzer`는 무반응 시간과 산소포화도 저하 시간을 내부 상태로 보관합니다.

블루투스 재연결 또는 세션 전환 시에는 `resetTimers()`를 호출해 다음 값을 초기화합니다.

- `motionStartTime`
- `spo2LowStartTime`

심박 이동 평균 기록(`hrHistory`)은 현재 유지됩니다. 작업 세션 단위로 심박 평균까지 완전히 초기화해야 한다면 별도 초기화 로직을 추가해야 합니다.
